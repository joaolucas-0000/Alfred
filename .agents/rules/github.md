# Regras para GitHub

- Use somente o MCP do GitHub já configurado; não instale, configure ou solicite outra integração.
- Antes de qualquer escrita, verifique o repositório, a branch e o objetivo da operação.
- Consulte repositórios, branches, commits, issues e pull requests quando solicitado.
- Analise alterações locais e sugira commits sem executá-los por conta própria.
- Antes de criar commit, push ou pull request, apresente o resumo das mudanças e solicite aprovação explícita para a operação específica.
- Solicite aprovação explícita antes de qualquer outra operação externa que modifique o GitHub, incluindo criar issues ou branches remotas.
- Nunca faça force push, sobrescreva histórico ou exclua repositórios.
- Nunca modifique secrets, tokens, webhooks, equipes, colaboradores ou configurações críticas.
- Não faça merge automaticamente e respeite branches protegidas.
- Evite commits diretamente na branch principal; prefira uma branch específica para cada alteração quando autorizada.
- Antes de um commit autorizado, verifique diff e status; use mensagem descritiva.
- Acompanhe CI quando disponível e relate apenas os resultados observados.
- Informe URL ou identificador do recurso criado quando o MCP retornar essa informação.
- Não afirme que uma operação foi concluída sem validar a resposta do MCP.
- Se uma chamada falhar ou retornar estado ambíguo, verifique o estado antes de tentar novamente e não repita uma escrita incerta.
